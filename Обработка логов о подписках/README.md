# Проект: Обработка логов о подписках

**Тип задачи:** анализ логов подписочного сервиса  
**Источник:** лог-файл `auto_purchase.log`  

## Описание проекта

Сервис ведёт логи операций с подписками. В логах фиксируются успешные продления, ошибки списания и количество пользователей с активным автопродлением. Задача — написать три функции для автоматического анализа этих логов и расчёта ключевых метрик.

## Задача 1: Статистика успешных и неуспешных продлений

Функция `count_success_and_failure` принимает путь к лог-файлу и подсчитывает количество успешных и неуспешных попыток продления. Успешные определяются по строке `Обновляем подписку пользователю id:`, неуспешные — по строке `ошибка при списании`. Функция возвращает кортеж из двух целых чисел: количество успешных попыток и количество ошибок. Из успешных попыток вычитаются ошибочные, чтобы исключить дублирование в рамках одной транзакции.

**Результат:** 1034 успешных продления и 186 ошибок. Конверсия — около 85%, что является хорошим показателем для подписочного бизнеса.

## Задача 2: Динамика автопродлений

Функция `auto_renewal_sub` принимает путь к лог-файлу и отслеживает количество пользователей с активным автопродлением в динамике. Логи парсятся, для каждого дня берётся максимальное значение показателя. Затем строятся два сглаженных ряда: скользящее среднее и скользящая медиана по всем предыдущим дням, включая текущий. Результат сохраняется в файл `auto_renewal_sub.txt`.

В данных обнаружена точка перелома — после примерно 220-го дня произошёл резкий рост автопродлений. Возможные причины: маркетинговая кампания, сезонность, изменение продукта.

## Задача 3: Распределение продлений по дням недели

Функция `sub_renewal_by_day` принимает путь к лог-файлу и анализирует, в какие дни недели пользователи чаще продлевают подписки. Все успешные продления группируются по дню недели на русском языке, подсчитывается количество. Результат записывается в файл `weekdays.txt`.

**Самые активные дни:** среда и четверг. Наименее активные: понедельник и суббота. Это можно учитывать при планировании маркетинговых активностей и технических работ.

## Используемые библиотеки

- `datetime` — парсинг дат из логов
- `statistics` — расчёт медианы
- `collections.Counter` — подсчёт по дням недели
- `pandas` — проверка результатов
