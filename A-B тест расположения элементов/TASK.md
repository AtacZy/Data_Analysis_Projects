# Итоговый проект: A/B-тест Marketpele

## Описание

Список объявлений Marketpele содержит "органические" и "платные" элементы. Платные элементы — это рекламные объявления, при нажатии на них пользователи переходят на страницу рекламодателя и приносят доход Marketpele. Органические элементы — это контент издателя, при нажатии на них пользователи переходят на другую статью от того же издателя.

У вас есть датасет `user_activity_data`, содержащий информацию о действиях пользователей на сайте.

## Данные для дизайна теста

- **Date** — дата
- **user_id** — идентификатор пользователя
- **Device** — тип устройства
- **pages_viewed** — количество просмотров страниц
- **paid_clicks** — количество кликов на рекламные объявления
- **organic_clicks** — количество кликов на органические ссылки
- **Revenue** — доход от действий пользователей

## Данные для анализа результатов

- **user_id** — идентификатор пользователя
- **pages_viewed** — количество просмотров страниц
- **paid_clicks** — количество кликов на рекламные объявления
- **organic_clicks** — количество кликов на органические ссылки
- **Revenue** — доход от действий пользователей
- **Device** — тип устройства
- **ctr_paid** — CTR по рекламным объявлениям
- **ctr_organic** — CTR по органическим ссылкам
- **Group** — группа пользователя в тесте

## Структура проекта

Итоговый проект состоит из 2 больших блоков:

1. Дизайн теста
2. Анализ полученных результатов

### Блок 1. Дизайн теста

Для дизайна теста используется датасет `user_activity_data` — набор исторических данных. Необходимо:

- Ознакомиться с данными
- Провести EDA
- Провести предобработку данных
- Получить дизайн теста

**Гипотеза:**

Изменение расположения платных и органических элементов повлияет на конверсии в клики по платным и органическим элементам, из-за чего изменится выручка.

### Блок 2. Анализ результатов

Для анализа используется датасет `experiment_data`. У каждого пользователя указана группа и его метрики. Цель — сделать вывод о наличии различий между группами и дать рекомендации бизнесу.

## Задания

### 1. Предобработка данных

a. Все ли колонки имеют подходящий тип?

b. Нет ли пропусков в данных?

c. Обработайте пропуски и выбросы при их наличии.

d. Как изменились метрики после удаления выбросов?

### 2. Изучите датасет

a. Сколько пользователей в него попало?

b. За какой период представлены данные?

c. Проанализируйте распределения метрик (violin plot).

d. Подробнее остановитесь на типе используемого устройства. Различаются ли метрики в зависимости от него?

e. Постарайтесь объяснить наблюдаемые закономерности.

f. Изучите активность пользователей.

g. Добавьте 2 метрики конверсии: из просмотров в платные клики и органические.

h. Есть ли какие-то закономерности в конверсиях?

i. Постройте корреляции между метриками.

### 3. Проведите дизайн теста

a. Зафиксируйте точно бизнес-контекст.

b. Сформулируйте гипотезу. Распишите H0 и H1.

c. Выберите метрики.

d. Выберите уровень значимости и мощность теста.

e. Составьте таблицу возможных дизайнов теста: посчитайте MDE для нескольких вариантов длительности теста (2, 3, 4 недели).

f. Для каждого из вариантов длительности убедитесь в том, что дизайн корректный. Проведите AA-тест (FPR по выбранным метрикам должен быть в районе выбранного уровня значимости). Проведите симуляцию A/B-теста для оценки мощности.

g. Подсказка: используйте CUPED. По некоторым метрикам может не получиться достигнуть желаемой мощности — это нормально. Постарайтесь получить максимальную мощность.

h. Пропишите итоговый дизайн, отразив в нём все параметры:

- Длительность
- Доля трафика
- Метрики
- MDE
- Наличие CUPED
- Способ обработки выбросов
- Гипотеза

### 4. Проведите анализ результатов теста

a. Ознакомьтесь с датасетом.

b. Проверьте значимость различий метрик между группами.

c. Сделайте выводы и рекомендации для бизнеса.

### 5. Составьте презентацию

a. Описание бизнес-контекста.

b. Гипотеза.

c. Выбранные метрики.

d. Результаты теста.

e. Интерпретация результатов.

f. Рекомендации по дальнейшим шагам.
